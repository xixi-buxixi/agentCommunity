### 1.2 Redis 判定

代码检查（`RateLimitService`、`RankingServiceImpl`、`HotNewsServiceImpl`）确认 Redis 是**旁路依赖**：

- `RateLimitService.tryConsume` 整体 try/catch，异常时 `return true`（**fail-open**，限流失效但不拦请求）；
- 排行有 MySQL 回退路径（`getFromRedis` 捕获异常 → 走 MySQL）；
- 热点新闻仅缓存。

因此未安装 Redis。后端正常启动并跑完全部剧本；唯一可见影响是
`/actuator/health` 返回 `DOWN`（Redis 健康指示器），业务不受影响。
**未覆盖项**：Redis 在位时的限流与排行缓存路径（见 §7）。

## 3. P0-1：后端在真实数据库上无法启动（真缺陷）

### 3.1 现象

用未修改的仓库源码打出的 jar 启动，**Spring 上下文创建失败，进程退出**：

```
ERROR o.m.spring.mapper.MapperFactoryBean : Error while adding the mapper
  'interface com.pulse.mapper.AgentMemoryMapper' to configuration.
org.apache.ibatis.builder.BuilderException: Error creating document instance.
  Cause: org.xml.sax.SAXParseException; lineNumber: 1; columnNumber: 143;
  元素内容必须由格式正确的字符数据或标记组成。
...
ERROR o.s.boot.SpringApplication : Application run failed
  UnsatisfiedDependencyException: Error creating bean with name 'agentWakeProcessor'
    -> 'agentMemoryServiceImpl' -> 'agentMemoryMapper'
```

注意失败链路是 `agentWakeProcessor → agentMemoryServiceImpl → agentMemoryMapper`：
**记忆系统与唤醒系统都挂在这条链上，所以这不是某个接口 500，而是整个应用起不来。**

### 3.2 根因

`pulse-backend/src/main/java/com/pulse/mapper/AgentMemoryMapper.java` 中，两处被
`<script>` 包裹的注解 SQL 含**未转义的裸 `<>`**。MyBatis 的
`XMLLanguageDriver.createSqlSource` 只要脚本以 `<script>` 开头就会**按 XML 解析**，
裸 `<>` 属于非法 XML：

| 行 | 方法 | 违规字面量 |
| --- | --- | --- |
| 121-127 | `deprecateTraitsForAgent` | `"AND status <> 2 AND deleted = 0 AND id IN "` |
| 192-197 | `deprecateByIds` | `"WHERE deleted = 0 AND status <> 2 AND id IN "` |

同文件第 179 行的 `applyOwnerEdit` **写法是正确的**（`status &lt;&gt; 2`），说明作者知道要转义，
只是漏了这两处。

修法（协调者决定谁落）：把这两处的 `<>` 改成 `&lt;&gt;`，与第 179 行保持一致。

> 不受影响的写法：非 `<script>` 的普通 `@Select` 里的 `<>`（如第 81/135/144 行）是安全的，
> 因为它们走纯文本路径，不做 XML 解析。`resources/mapper/AgentMapper.xml` 单独校验通过。

### 3.3 全仓扫描结果 + 为何单测抓不到

用脚本（`scratchpad/scan_mappers.py`）扫描 `com/pulse/mapper/` 下全部 17 个 Mapper 的
`<script>` 注解 SQL，剔除合法 MyBatis 标签后检查残留 `<`/`>`：

```
AgentMemoryMapper.java:121: RAW ANGLE BRACKET in <script> SQL
    literal: 'AND status <> 2 AND deleted = 0 AND id IN'
AgentMemoryMapper.java:192: RAW ANGLE BRACKET in <script> SQL
    literal: 'WHERE deleted = 0 AND status <> 2 AND id IN'

total offending literals: 2
```

**全仓仅此 2 处**，均在本轮新增的 `AgentMemoryMapper`；Phase 3 的 `AgentWakeEventMapper` 干净。

**为什么 233 个单测全绿**：这些测试全部 mock `AgentMemoryMapper`，
MyBatis 的 `Configuration` / `SqlSource` 从不被构建，XML 解析这一步根本没发生。
**建议**（Pending）：补一个最小的 Spring 上下文启动测试（或 MyBatis
`Configuration.addMapper` 冒烟测试），把「注解 SQL 能被解析」纳入 CI，否则同类问题会再次
穿过 200+ 单测直达部署。

### 3.4 本报告 E2E 是在什么上面跑的

为了不违反「不修改业务代码」红线，同时又能产出剧本证据：

1. `rsync` 把 `pulse-backend/` 复制到 `scratchpad/backend-patched/`（排除 `target`、`.git`）；
2. **只在副本里**把上述 2 处 `<>` 改为 `&lt;&gt;`；
3. `mvn package -DskipTests` 构建副本，用该 jar 跑剧本 1-4。

仓库内 `AgentMemoryMapper.java` **保持未修改**（已核验：仓库文件仍含裸 `<>` 字面量 1 处，
副本含转义版 1 处）。**剧本 1-4 的结论因此成立于「补丁后」的代码；
补丁未落地前，这些功能在真实环境中全部不可用。**

### 5.3 剧本 3：预算演练 —— **通过**

前置：Agent 2 `daily_wake_budget=2`，`wake_count_today` 归零，`next_wake_at` 推到
2026-07-30（排除作息唤醒干扰，只测事件唤醒），`used_tokens` 基线 **150**。

> 配置说明：本剧本额外设 `AGENT_MAX_EVENTS_PER_WAKE=1` 并重启后端。
> 默认值 10 会让 6 个事件**在一次唤醒里被合并消费**（这本身是正确且符合设计的行为
> ——「五条回复是一次对话」），但那样预算就不是约束条件，测不到上限。设为 1 后每次唤醒
> 消费 1 个事件，6 个事件需要 6 次唤醒，而预算只有 2 —— 预算成为唯一约束。
> 同时关闭 `MEMORY_REFLECTION_ENABLED` 以保证 token 增量只来自唤醒。

| # | 断言 | 实际 |
| --- | --- | --- |
| 1 | 一次性插入 6 条不同 `dedup_key` 的 PENDING 事件 | 6 条 PENDING（`2:TIPPED:LEDGER:101..106:HUMAN:1`） |
| 2 | `dedup_key` 唯一性 | 故意重插 `...:101:...` → `ERROR 1062 Duplicate entry for key 'agent_wake_events.uk_dedup_key'` |
| 3 | **唤醒次数 ≤ 2** | **恰好 2 次**：@21:28:27、@21:29:27（间隔正好 1 分钟，防抖生效）；`wake_count_today=2` |
| 4 | **剩余事件仍 PENDING** | 2 条 `PROCESSED`（101,102），**4 条仍 PENDING**（103-106，`processed_at=NULL`）—— 符合「预算耗尽保留至次日」策略，未被丢弃/SKIPPED |
| 5 | **无重复扣费** | `used_tokens 150 → 450`，增量 **300 = 2 × 150**；mock decision 调用数 `4 → 6`，增量 **2**。**扣费与调用数严格一致** |
| 6 | 持续跑 tick 不越界 | 之后又跑 ~4 分钟（≈24 个 tick），四次采样 `wake_count_today` 恒为 2、PENDING 恒为 4、`used_tokens` 恒为 450 —— **预算硬顶住** |

`agent_logs` 佐证（Agent 2 三条，第一条是剧本前的作息唤醒）：

