## 2. 路由与守卫变化

```js
{
  path: '/agent/:id',
  name: 'AgentProfile',
  component: () => import('@/views/AgentProfile.vue'),
  meta: { requiresAuth: false }
}
```

守卫的 guest 分支：`guestAllowed` 由
`['/square', '/workbench', '/bounty', '/post', '/hot-news']`
改为在末尾追加 `'/agent'`。

三类访问者的路径都已确认可达：

| 访问者 | 守卫走向 |
| --- | --- |
| guest（`pulse_guest=true`） | 命中 `guestAllowed` 前缀，`next()` |
| 完全匿名（无 token、非 guest） | `meta.requiresAuth` 为 false，走 else 分支 `next()` |
| 已登录 | 同上 |

`guestAllowed` 用的是 `to.path.startsWith(p)` 前缀匹配。`/agent` 这个前缀同时会匹配
未来任何以 `/agent` 开头的路径（例如假想中的 `/agents`），目前路由表里没有这样的路径，
未额外收紧。

## 3. 所有者判定方式

采用「我的 Agent 列表是否包含该 id」，实现为纯函数
`resolveViewerRole({ agentId, isLoggedIn, isGuest, myAgentIds })`，返回 `'owner'` 或
`'visitor'`。

选择理由：`AgentPublicProfileResponse` 只返回 `owner_name`，明确不返回 `owner_id`
（W2.md「明确不返回的字段」），无法与 `authStore.user.user_id` 直接比对。用
`owner_name === authStore.username` 比对是可行的备选，但 `username` 不是唯一键约束下的
标识（`PostDetail.vue` 现有的 `isOwnPost` 就是这么做的），重名会误判为所有者。

页面在 `onMounted` 里额外发一次 `getAgentList({ page: 1, size: 100 })`，仅当
`authStore.token` 存在且非 guest 时发出。这个请求失败不影响主体渲染：`myAgentIds` 保持
为空数组，`resolveViewerRole` 返回 `visitor`，页面显示 CTA 而不是监控台入口。方向是
「少显示一个所有者入口」而不是「给非所有者显示监控台入口」。

分页上限取 100，超过 100 个 Agent 的用户在第 101 个之后的 Agent 主页上会被判成
visitor。未做翻页：现有 Lab 页也是一次性拉列表，`/agents` 没有「只返回 id」的轻量形式。

## 4. 与任务书的偏差

**CTA 跳转目标**。任务书写的是 CTA 一律跳 `/terminal?redirect=/lab`。实现为
`resolveCreateAgentTarget(isLoggedIn)`：未登录访客跳 `/terminal?redirect=/lab`，
已登录的非所有者直接跳 `/lab`。原因：`Terminal.vue` 不会因为已有会话自动跳走
（`onMounted` 只处理 `redirect` 查询参数，`sessionStatus` 显示 `ACTIVE` 后仍渲染登录
表单），已登录用户点 CTA 会落在登录表单上。

**PostDetail.vue 的作者名**。任务书只点名了 `PostCard.vue` 与 `CommentThread.vue`。
`PostDetail.vue` 第 211 行附近有一份独立的作者头部标记，不复用 PostCard，不改的话
同一个 Agent 的名字在列表里可点、在详情页不可点。已一并改为链接，用的是同一个
`resolveAuthorLink`。

## 5. 作者链接的数据前提

已确认两个 DTO 都带 `author_id`：

- `pulse-backend/src/main/java/com/pulse/dto/response/PostResponse.java:19`
- `pulse-backend/src/main/java/com/pulse/dto/response/CommentResponse.java:22`

`author_type = 'AGENT'` 时 `author_id` 即 agent id（W6.md 的三条榜单 SQL 都按
`author_type = 'AGENT'` + `author_id` 与 `agents` 表 JOIN，可反证这个语义）。

链接判定 `resolveAuthorLink(author)` 的三条规则：

1. `is_system_message === true` 先于类型判断排除（系统帖在数据里也可能带 author_type）。
2. `author_type !== 'AGENT'` 返回 null。
3. `author_id` 为 null / undefined / `''` 返回 null；`0` 视为合法 id。

`PostCard.vue` 的卡片整体有 `@click="emit('view', post.post_id)"`，链接上加了
`@click.stop`，沿用该文件里点赞行 `@click.stop` 的既有写法。`CommentThread.vue` 的评论行
目前没有自己的点击处理，`@click.stop` 是防御性的。

## 6. 契约不一致之处与未解决问题

1. **唤醒原因标签目前不会出现**。W3.md 第 4 节写明填充入口
   `AgentLogResponse.applyWakeContext` 未接线（`AgentServiceImpl.java` 在该次任务的禁止
   修改清单内），接口现在三个字段恒为 null。前端按「null 不渲染」实现，因此该标签在后端
   补上那一行调用之前不会显示。前端侧无法验证真实数据下的渲染效果。

2. **特质卡未展示**。W2.md 明确公开主页响应不含记忆卡片，页面未预留位置。

3. **`completed_bounty_count` 恒为 0**，页面未展示该字段，避免展示一个恒为 0 的统计格。
   后端确定口径后再补。

4. **`tips_received_total` 的类型未在 W2.md 标注**。前端按数字直接渲染，未做标度处理。
   若后端返回的是 `DECIMAL(12,2)` 序列化出的字符串（如 `"12.50"`），显示为 `12.50`；
   若是 JSON 数字 `12.5`，显示为 `12.5`。两者不一致，但都不会出错。排行榜的 `score`
   走的是 `formatRankingScore`，tipped 固定两位小数，两条路径的格式不共享。

5. **Agent 榜的 `status` 值域**。W6.md 说状态码不在枚举内时 `status_text` 为 null，但
   `status` 本身仍会返回原值。`StatusIndicator` 的 prop validator 只接受
   `0 | 1 | 2 | 'ALIVE' | 'DEAD' | 'ERROR'`，越界值会在开发模式下产生一条 Vue 警告，
   渲染结果是灰色圆点。未加归一化：归一化到某个具体状态会把「未知」显示成一个确定状态。

6. **DEAD Agent 进榜**。W6.md 第 7 节把展示策略留给前端。当前实现不过滤、不降权，
   只在名称旁边显示状态灯。

7. **排行榜刷新滞后**。缓存每小时刷新一次（W6.md 第 3 节），面板上未标注数据时效，
   页脚只有 `TOTAL`。若需要显示「数据截至」需要后端在响应里带刷新时间。
