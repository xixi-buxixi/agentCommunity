## 与 X2.md 的字段核对

| 项 | X2 | 前端 | 结论 |
| --- | --- | --- | --- |
| PATCH 请求字段 | `is_public`（Boolean，可选） | 只带 `is_public` 一个字段 | 一致 |
| PATCH 响应字段 | `AgentMemoryResponse` 新增 `is_public`，同时保留 `scope` | 优先读 `is_public`，缺失时回退 `scope === 'PUBLIC'` | 一致 |
| 事实卡设公开 | 99900/400 | 文案「只有特质卡可以公开」 | 一致 |
| 已废弃卡设公开 | **20008/409**，不是 99900 | 已按 20008 单独给文案「已废弃的记忆不可公开」；按钮对 DEPRECATED 卡隐藏，该文案只覆盖读列表之后被系统废弃的时间窗 | 已按 X2 修正 |
| 撤回方向（`false`） | 任意类型、任意状态均接受 | 按钮只对特质卡显示，撤回不额外限制 | 一致 |
| 已禁用卡 | `scope` 与 `status` 互不影响，禁用不撤回公开 | 已禁用的特质卡仍可切换公开 | 一致 |
| `public_traits` 每项 | `memory_id` / `content` / `confidence_score` / `created_at` | 四个字段同名读取 | 一致 |
| `public_traits` 上限与排序 | 20 条，SQL 内 `LIMIT`，按置信度降序 | 前端不再排序与截断，直接按响应顺序渲染 | 一致 |
| 记忆表缺失时 | `public_traits` 返回空数组，profile 其余部分正常 | 空数组与字段缺失渲染同一个空态「该 Agent 尚未公开任何特质」 | 一致 |
| `completed_bounty_count` | 该 Agent 发布、`status=2`（COMPLETED）且已结算的悬赏，生涯累计无时间窗 | 统计区标签「发布并完成的悬赏」 | 一致 |

需要注意的一处口径差异：X2 未解决问题 6 提到该字段无时间窗，与排行榜的 7/30 天窗口不同。公开主页的统计区四项原本就都是生涯累计，第五格与它们同栏，未与榜单并排展示，因此未加额外注明。

## 未解决问题

1. 后端改动尚未合入本工作树：`pulse-backend/src` 中仍无 `is_public` / `public_traits`，`AgentProfileServiceImpl` 仍把 `completedBountyCount` 写死为 0。核对只依据 X2.md 的文本，未对运行中的接口验证。两侧合并后需回归三处展示。
2. 未做浏览器实机验证：本机 8080 无后端进程，记忆面板需登录且需要 `agent_memories` 表，无法在无会话状态下走到切换按钮与公开主页的新区块。
3. `public_traits` 对所有者与访问者返回同一份数据（X2 未解决问题 2），所有者在自己的公开主页上看不到未公开的特质。前端未对所有者做任何补偿展示，只在该区块下方给出到监控台的链接。
4. 多实例部署下公开状态最多 30 秒后才在公开主页可见（X2 未解决问题 4）。前端切换成功后就地更新面板内的标记，但未提示公开主页存在延迟。
5. 统计区由四格改为五格（`sm:grid-cols-4` → `sm:grid-cols-5`），「发布并完成的悬赏」标签在窄屏下会折行。未做实机截图确认折行后的行高是否与其余四格一致。
6. 切换按钮与其余操作共用 `pendingId`，同一时刻只允许一张卡在写入中。这是面板原有行为，未改动。
