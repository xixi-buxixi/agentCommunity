# tests/data

## prompt_baseline_pre_phase2.json

A golden sample of the decision prompt as it was **before** the Phase 2 memory
work (`docs/goal-memory-and-wakeup-plan-2026-07-28.md`). Consumed by
`TestPrePhase2GoldenSample` in `tests/test_memory_and_reflection.py`, which
asserts byte-for-byte equality of both messages (`enhanced_system` and
`user_message`) when a request carries no usable memories.

### Provenance

| | |
|---|---|
| Baseline commit | `8afc087` (`fix: 前端发布不再删除旧 assets…`, 2026-07-28) — the last commit before the Phase 2 AI Side changes |
| Last commit touching the reference file | `319c3d1` (`pulse-ai-side/app/services/prompt_builder.py`) |
| Generated by | `tests/data/generate_prompt_baseline.py` |
| Cases | `single_post`, `multi_post`, `one_hostile_post` (the last one also pins the injection filter's placeholder output) |

The snapshot is the output of the **baseline commit's** `prompt_builder.py`, not
of the current working tree. That is the whole point: it is the only assertion in
the suite that can catch "Phase 2 quietly changed the prompt of every agent that
has no memories yet". Comparing the current implementation with itself (e.g.
`build_full_prompt(...)` vs `build_full_prompt(..., memories=None)`) proves
nothing and was rejected in review.

### When regeneration is allowed

Regenerating is a **baseline change**, not a test fix. A failure here means the
prompt sent to agents without memories differs from the pre-Phase-2 prompt.

- **Not allowed**: to make a failing test pass, or as a side effect of any change
  that is supposed to be memory-only / backward compatible. Fix the code instead.
- **Allowed** only when the prompt change is *intended and approved* — a
  deliberate evolution of the decision prompt (new action type, reworded output
  format or data-boundary section, etc.). In that case:
  1. land the prompt change and confirm the golden diff contains **only** what
     you intended (review the diff line by line — this file is human readable);
  2. regenerate with the reference file taken from the **new** approved commit;
  3. update the Provenance table above (new baseline commit + date + reason);
  4. note the baseline update in the task record
     (`agentsPrompt/modules/ai-side/tasks.md`) so the change is auditable.

Never hand-edit the JSON: it must always be machine-generated output of a real
implementation.

### How to regenerate

From the `pulse-ai-side` directory:

```bash
# 1. extract the reference implementation from the (new) baseline commit
git show <BASELINE_COMMIT>:pulse-ai-side/app/services/prompt_builder.py \
    > /tmp/prompt_builder_baseline.py

# 2. regenerate the snapshot from THAT file (never from the working tree)
python tests/data/generate_prompt_baseline.py \
    /tmp/prompt_builder_baseline.py \
    tests/data/prompt_baseline_pre_phase2.json

# 3. verify
pytest tests/test_memory_and_reflection.py -k GoldenSample -v
```

The generator loads the extracted file directly (`importlib`), sets the
environment variables the settings singleton requires, and writes the cases
defined at the top of the script. Adding a case is safe; changing or removing one
weakens the guarantee for that prompt shape and should be called out in review.

`TestPrePhase2GoldenSample` also contains a reverse sentinel
(`test_memories_do_change_the_prompt`): if the memory block ever stops being
rendered at all, the golden test would pass vacuously, and that sentinel fails
instead.
